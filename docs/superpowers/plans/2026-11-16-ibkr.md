# IBKR Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Track two Interactive Brokers accounts in trodki, with:
- live read-only positions (options first-class) counted in net worth, shorts as liabilities
- a dedicated IBKR positions page
- full Flex history as history events, with IBKR-reported realized PnL

**Architecture:**
- New exchange module `rotkehlchen/exchanges/ibkr/`. Each IBKR account is one exchange connection (location
  `ibkr`).
- Positions come from the locally running Client Portal Gateway, using only `/portfolio/*`, `/tickle` and
  `/sso/validate`. History comes from Flex Web Service, plus manually exported yearly Flex XML files.
- Contracts become `CustomAsset`s keyed by conid. A narrow liabilities hook lets an exchange report liabilities into
  the totals.

**Tech Stack:** Python 3.14 (Flask API, gevent, `requests`, stdlib `xml.etree`), Vue 3 + TypeScript + Pinia +
`@rotki/ui-library`, pytest, vitest.

**Spec:** `docs/superpowers/specs/2026-11-16-ibkr-design.md`. Read it before starting any task.

## Global Constraints

- **Never build or call an `/iserver/*` URL.** The gateway client's URL builder raises on it, and a guard test
  enforces it.
- **Outbound hosts:** the configured gateway URL, and the Flex Web Service host returned by IBKR (in the
  `ndcdyn.interactivebrokers.com` family). Nothing else.
- **TLS verification** is off only when the gateway host is `localhost` or `127.0.0.1`.
- **Pacing:**
  - Global limit 10 req/s. Use a limiter at 5 req/s with burst 5 per gateway.
  - `/portfolio/accounts` at most once per 5 s, `/tickle` at most 1/s.
  - A 429 means no calls to that gateway for 900 s, and the error is surfaced. No retry loop.
- **Location** identifier `ibkr`, display name `Interactive Brokers`.
- **Contract asset** identifier is `ibkr-<conid>`. `custom_asset_type` is one of `IBKR Stock`, `IBKR ETF`,
  `IBKR Option`, `IBKR Other`.
- **Connection credentials:** `api_key` = Flex token, `api_secret` = Flex query id.
- **Connection settings:**
  - `ibkr_gateway_url` (default `https://localhost:5000`)
  - `ibkr_account_id` (optional override)
- **History `unique_id`:** `ibkr-<account>-<TradeID>` for fills. Other sections use their Flex ids, like
  `ibkr-<account>-<section>-<id>`.
- **Flex `DateTime`** is US Eastern time, in two formats: `YYYYMMDD;HHMMSS` and `YYYY-MM-DD HH:MM:SS`.
- **Backend style:**
  - Every new constant uses `Final`.
  - Catch narrow exceptions (`RemoteError`, `requests.RequestException`, `XMLParseError`), never
    `except Exception`.
  - Iterate cursors directly; don't call `fetchall()` first.
- **Fork rules:** new code lives in new modules. Upstream files change only at registration points, and every one
  is named in a task.
- **Frontend rules** (repo `CLAUDE.md`):
  - Use `get()`/`set()` and explicit types on refs and computed values.
  - `useI18n({ useScope: 'global' })`.
  - Stores hold state only.
  - `.ts` files are capped at 400 lines.
  - `data-testid` values are kebab-case.
  - Locale keys are sorted.
- **Tests:** no VCR and no live calls. Gateway and Flex use fixture JSON/XML under
  `rotkehlchen/tests/data/ibkr/`, with fake account ids `U0000001` and `U0000002`.
- **Running on this PC:**
  - Backend tests: `VCR_BRANCH=develop .venv/Scripts/python.exe -m pytest ...`
  - The app needs the env vars in `CLAUDE.md` > Windows.
  - Frontend commands run from `frontend/`.
- **Commits:** title ≤ 50 chars. End each message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **One gateway down or logged out while the other works.** That connection reports an error. The other
   connection's balances and positions still return. Nothing is silently zeroed. (Task 4 test
   `test_one_gateway_down_other_still_reported`.)
2. **The same conid held in both accounts.** One asset, two balances, attributed per connection. (Task 3 test
   `test_same_conid_two_accounts_one_asset`.)
3. **Zero-size rows** (closed today, or expired but still listed with `position == 0`). They are skipped in balances
   and on the page. (Task 4 test `test_zero_position_rows_skipped`.)
4. **No FX price for a position currency** (e.g. CHF). The connection reports an error naming the currency instead
   of valuing at 0. (Task 4 test `test_missing_fx_rate_is_an_error`.)
5. **Overlapping or incomplete Flex files.**
   - Re-importing an overlapping year adds nothing.
   - A statement missing a required section fails with an error naming the section.
   - (Task 9 tests `test_import_overlapping_statements_dedupes` and `test_missing_section_named_in_error`.)

### Task 8: Flex → history events, history sync, realized PnL

**Files:**

**Interfaces:**
- Consumes: `FlexStatement` (Task 7), `get_or_create_contract_asset` (Task 3).
- Produces `flex_to_events(database: DBHandler, statement: FlexStatement, location_label: str) ->
  list[HistoryBaseEntry]`.
  - **Fills** go through `create_swap_events`:
    - A buy spends `|trade_money|` in `currency` and receives `|quantity|` of the contract.
    - A sell is the reverse.
    - The fee is the commission in its currency.
    - `extra_data` holds `{'ibkr': raw, 'fifo_pnl_realized': str, 'open_close': …, 'notes': …}`.
  - **Sell-to-open:** pick the event shape trodki accounting treats as opening a short, so the contract becomes a

      happens on cover.

  - **CASH trades** become fiat-to-fiat swaps with `extra_data['ibkr_fx_conversion'] = True`.
  - **Deposits and withdrawals** become `AssetMovement`s. Dividends, interest and fees become `HistoryEvent`s with
    matching types.
  - **Splits** become an adjustment pair on the same asset identifier. Unsupported corporate action types trigger a
    `msg_aggregator` warning and are skipped.
  - Every event has `location=LOCATION_IBKR`, `location_label=<connection name>` and a deterministic `unique_id`
    (per Global Constraints).
- Produces `realized_pnl(database, connection_name, from_ts, to_ts) -> dict[str, FVal]`: currency → the sum of
